# Universities Integration

Date: 2025-10-24

This document explains how the app sources and uses universities, why we don’t auto-import from Hipo, and how signup resolves a valid `university_id`.

## Source of truth

- Canonical records live in our Supabase `public.universities` table.
- Each row has an internal UUID primary key (generated by the database) and a unique `domain` when available.
- Student profiles reference this table via `students.university_id` (FK).

## Why not auto-import from Hipo

- Hipo is a discovery source (name/domains), not authoritative. Auto-import can create duplicates or incorrect entries.
- We may need multiple domains per university and additional metadata; we prefer curated inserts with verification.
- Internal UUIDs should remain stable and independent of external inputs.

## App behavior

1. Public list endpoint (pre-auth):
   - `GET /api/universities` → `{ ok, universities: [{ id, name, domain }] }`
   - Server-side Supabase client. If `SUPABASE_SERVICE_ROLE_KEY` is set, it bypasses RLS for read; otherwise falls back to anon.
   - Used by `src/app/signup/page.tsx` to populate the dropdown before login.

2. Hipo-backed search (optional discovery):
   - `GET /api/universities/search?name=&country=` → `{ ok, results: [{ name, country, domains, match: { id, name, domain } | null }] }`
   - Server calls Hipo API and maps returned domains to our internal rows.
   - UI can show suggestions, but only selections with a `match` should be allowed for signup (they have a valid internal UUID).

3. Ensure student on auth:
   - `ensureStudentProfile` can infer `university_id` by matching the user’s email domain with `universities.domain` if metadata is missing or invalid.
   - If no match is found, profile creation is skipped with `{ reason: 'missing_university_id' }` and the UI prompts the user to complete their profile.

## Middleware and caching

- `middleware.ts` excludes `/api/universities*` so the endpoints are accessible pre-auth.
- `public/sw.js` uses a stale-while-revalidate strategy for `/api/universities*` to improve resilience and UX.

## Environment variables

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (required)
- `SUPABASE_SERVICE_ROLE_KEY` (optional, server-only)
  - When provided, `/api/universities` can read through RLS pre-auth. Never expose this key client-side.

## Onboarding a new university

1. Detect: A user with an unknown email domain or a search via the Hipo endpoint signals a missing university.
2. Verify: Confirm domain ownership (e.g., verified email, DNS TXT, or .well-known file).
3. Insert: Create a curated row in `public.universities` (name, primary domain, optional country/slug). The database generates the UUID.
4. Map: Optionally maintain a secondary `universities_domains` table for multiple domains pointing to the same university.
5. Result: Signup and ensure-student will now resolve `university_id` correctly via dropdown or domain inference.
